    Optionalselection

    selection?: { borderStyle?: SelectionBorderStyle; color?: string }

    The tooth-selection highlight.

    Selection is an interaction state, not artwork — it is drawn by the chart around a tile, not by any tooth drawing — but hosts look for it here when they are deciding "what colour is everything". It is applied through the existing session setters (setSelectionColor / setSelectionBorderStyle), so it is NOT a CSS custom property and does not appear on the themed element.

    The dedicated selectionColor / selectionBorderStyle props on the provider are the more specific control and win when both are given.

    Optionaltokens

    tokens?: Record<string, string>

    Any palette token by its full CSS custom-property name, for the surfaces OdontogramThemeConfig.tooth does not name — the per-material restoration colours (--odon-rest-gold, --odon-fill-composite, …) and the e.max / metal-ceramic gradient stops.

    Keys must start with --odon-; anything else is ignored, so this cannot be used to set unrelated custom properties on the host's element.

    Not every token is a colour. --odon-implant-tint is a CSS filter over the implant fixture as a whole: the drawing's ~65 metal greys encode a light source, so they are deliberately not themable one by one, and a filter shifts them together instead of flattening the shading. It is none unless set, and it does not touch the peri-implant bone-loss overlay, which sits outside the filtered group.

    --odon-implant-fill is the flat counterpart of that tint, for a palette that wants one solid colour rather than shaded metal. It is a colour, and it replaces the fill of every shape in the fixture at once. Each of those shapes falls back to the grey it is drawn in, so unset it changes nothing at all — there is no single default to state. The two compose: the fill flattens the fixture, the filter then shifts it. It leaves the peri-implant bone-loss overlay alone for the same reason the tint does, and the occlusal screw-hole rims keep their outline, because only fill is affected.

    Example

    { tokens: { "--odon-rest-gold": "#d4af37", "--odon-fill-composite": "#eae0c8" } }

    Example

    { tokens: { "--odon-implant-tint": "hue-rotate(205deg) saturate(.85)" } }

    Example

    { tokens: { "--odon-implant-fill": "#8fa6b8" } }

    Tooth-artwork colours.

    The drawings carry their colours as palette tokens with today's colour as the fallback (fill: var(--odon-tooth-body, #ebebeb)), so an omitted key leaves that surface exactly as drawn. Setting a key recolours that surface across BOTH anatomy profiles at once, even where the classic and measured artwork happen to be drawn in different shades.

    This is a curated subset. Every token — including the gradient stops and the per-material restoration colours — can be set by name through OdontogramThemeConfig.tokens.

    Type Declaration

    • Optionalbody?: string

      The tooth's own silhouette — crown AND root — and every broken or prepared variant of it.

      In the classic profile this is the whole tooth: those drawings are one shape, with no inner structure. In measured it is the outer shell — enamel over the crown, cementum over the root — around dentin below, which takes this colour unless it is set. Setting only body therefore looks the same in both profiles.

    • Optionalbone?: string

      Alveolar bone.

    • Optionalcalculus?: string

      Calculus deposit.

    • Optionalcaries?: string

      Caries body.

    • OptionalcariesOutline?: string

      Caries outline.

    • Optionalcusp?: string

      Occlusal cusp field.

    • Optionaldentin?: string

      The dentin core inside the crown and root (measured profile only — the classic drawings have no enamel/dentin boundary to colour).

      Unset, it follows body, so the boundary is invisible until you ask for it. The occlusal view has no core: nothing of the dentin shows from above.

    • Optionalgroove?: string

    • Optionalgum?: string

      Gingiva.

    • Optionalhighlight?: string

      Crown sheen (the "beauty" layer).

    • OptionalmilktoothBody?: string

    • OptionalmilktoothHighlight?: string

    • Optionaloutline?: string

      Crown and root outline.

    • OptionaloutlineDark?: string

      Dark structural outline.

    • OptionaloutlineWidth?: string

      The width of that outline, as a CSS length in SVG user units ("1", "1.4", "0.75"). Not a colour — it is here because it is the other half of outline above.

      It rides every layer that is the tooth's own silhouette, so the contour keeps one thickness whatever the tooth is charted as: a natural or deciduous crown, a root remnant, a prepared crown, a tooth under the gum, any of the seven fracture states, or the occlusal projection — whose tiles sit in the same chart grid as the side views and therefore widen with them. The occlusal grooves are deliberately not included and stay hairlines.

      Unset, the drawings declare no width at all and stroke at the SVG initial value of 1.

    • OptionalpulpHealthy?: string

      Healthy pulp chamber.

    • OptionalpulpInflamed?: string

      Inflamed pulp.

    • OptionalrestorationOutline?: string

      Restoration outline.

    • Optionalwear?: string

      Bruxism wear facet.
